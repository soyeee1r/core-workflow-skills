# 数据源与定位

## 必须配置的映射

在真实运行前，从统一项目状态中心或明确的人类输入获得：

```text
platform_key → 后台入口 URL / 官方接口
account_id → 平台内可核对的账号显示名
project_id → publication_id / content_id / canonical_url
project_id → target_doc_url
```

## 已确认平台配置

- `douyin`：使用用户 Chrome 中现有的抖音登录态。优先复用已打开的抖音创作者后台标签页；没有标签页时进入抖音官方创作者后台。用内容 ID 打开作品详情页，不得以内容管理列表作为唯一数据源；逐页检查“总览”“流量分析”“观众分析”“评论热词”“评论管理”，并在可用时截图记录回看率、跳过率/跳出率及其峰值片段。若登录失效，按登录阻塞流程提醒用户。
- `wechat_channels`：使用 Chrome 中的视频号助手/创作者后台。默认视为可能未登录；第一次真正到期取数时，如需扫码或验证，在原发布触发会话喊用户完成登录，再恢复同一任务。
- 不读取或保存两个平台的密码、Cookie、Token、二维码内容或恢复码。

## 平台读取顺序

1. 官方 API 或已授权 Connector；
2. 平台导出；
3. 用户现有浏览器登录态中的账号后台；
4. 前台公开页面仅作身份与公开数交叉核对。

使用浏览器前先按 `$chrome:control-chrome` 检查是否有更合适的 Connector/API。浏览器路线只操作指定平台、账号和视频；遇到登录或二次验证时暂停交给用户。

## 飞书文档

使用 `$lark-doc` 以 user 身份在用户“我的文档库/数据回收”目录创建和读写文档。命名规则固定为 `<正式项目名>-数据回收`；正式项目名缺失时使用 `<视频标题>-数据回收`。按 `project_id` 复用已有文档，不创建独立电子表格或第二份文档。文档内建立一张跨平台结构化对比表，以平台与指标为行、2h/6h/24h/48h 为数据列，并保留采集时间、口径、证据和快照 ID。创建时保存 `project_id`，将 doc token/URL 写入 Publication。同一期跨平台共用一份文档。写入后回读；权限不足时保留已验证快照并标记 `needs_human`。

## Automation 接口

事件层在可信发布消息到达时传入完整 Publication，并当场创建 `published_at + 2h/+6h/+24h/+48h` 四个精确触发窗口。宿主若不能用一个自动化表达四个准确时间，拆成四个单次自动化；台账仍保存四个独立窗口任务。创建后立即回读任务名称、时区、触发时刻、下一次运行时间和启用状态，确认没有“8h”等错误名称或偏移。每次到点只执行对应窗口，不重复扫描发布消息。进程重启时只恢复尚未执行的窗口；若已经超过 `run_at`，恢复后立即补跑并标记实际快照龄。

禁止用每小时、每日或其他 recurring heartbeat 扫描“是否到期”。宿主暂不支持事件创建单次延迟任务时，保持功能未启用并报告缺少触发适配器，不用轮询伪装实现。

持久化账本使用 `/Users/mac/.local/share/content-ops-agent/evidence-ledger/content-performance-state.json`；不存在时从 `assets/content-performance-state.json` 初始化。保存 Publication、单次任务、文档映射、快照状态、重试与提醒时间；禁止保存凭据。
