# 输出契约

## 文档对比表

标题使用 `<正式项目名>-数据回收`；没有正式项目名时使用 `<视频标题>-数据回收`。按 `project_id` 复用“我的文档库/数据回收”中的同一份飞书文档，不创建独立电子表格或第二份文档。正文只保留一张跨平台统一对比表：

```text
平台 | 指标 | 2h | 6h | 24h | 48h | 口径/备注
```

每个窗口另存采集时间、证据链接和 `metric_snapshot_id`。主文档面向运营与内容复盘，优先展示播放、赞评转藏、净增粉、封面点击、平均播放时长/占比、完播与早期跳出、回看/跳过峰值、核心流量来源、评论主题等；完整地域、逐条评论、全部章节排名、低占比来源、无复盘价值的零值和页面冲突原值放入证据附录或结构化原始快照。抖音的采集深度不得因正文删减而下降。

每个窗口另追加一段“阶段概述”，说明相对上一有效窗口的净增、增幅、增长是否放缓/加速及可由数据直接支持的运营或内容观察。2h 是基线，不强算环比；所有概述只追加，不覆盖。

证据附录保留以下窗口详情：

```text
发布后 <2h|6h|24h|48h> 数据｜<平台> · <账号> · <视频标题或内容 ID>

发布时间｜2026-08-07 10:00（Asia/Shanghai）
采集时间｜2026-08-08 10:12（发布后 24.20h，on_time）
内容链接｜<canonical_url>

核心指标
- 播放量：12,345
- 完播率：38.2%（平台口径：……）
- 点赞：456
- 评论：34
- 分享：21
- 收藏：18
- 新增关注：9

其他平台原始指标
- <原字段名>：<显示值>（<单位/口径>）

详情页检查
- 总览：已检查 / 不可用原因
- 流量分析：已检查 / 不可用原因
- 观众分析：已检查 / 不可用原因
- 评论热词：已检查 / 不可用原因
- 评论管理：已检查 / 不可用原因
- 回看率 / 跳出率证据：<精确值或峰值片段 + 截图>

数据证据｜<截图、导出或 API 响应链接/附件>
metric_snapshot_id｜ms_xxxxxxxxxxxxxxxx
```

只展示实际可用指标。不可用字段不必堆满正文，但需在结构化快照保留 `availability` 与原因。不要在这个区块写“表现好/差”或归因结论。

## 阶段回执

```text
<2h|6h|24h|48h> 数据回收已完成：<doc_url#anchor>
采集于发布后 <age>h，共写入 <count> 个指标；原始证据已附上。
```

## 48h 完整项目复盘与最终回执

48h 后在同一文档形成完整复盘，至少包含：项目与发布背景、双平台四窗口指标总表、相邻窗口净增/增幅、跨平台对比、观看与流量来源、受众与评论洞察、关键传播节点、数据质量与异常、可复用经验、问题及下一次发布行动项。缺失数据保持缺失，不做无证据归因。

48h 群通知同时承担阶段回执和最终回执，只发一次，不额外发送第五条消息。

```text
48h 数据回收及项目复盘已完成，2h/6h/24h/48h 四窗口对比如下：
- <指标>：<2h> → <6h> → <24h> → <48h>（相邻增量/增幅）
完整数据与证据：<doc_url>
```

## 阻塞回执

第一句说明卡点，再给唯一下一步：

- `未到窗口`：说明窗口和 `due_at`，保持 scheduled；
- `needs_login`：说明需要用户在哪个浏览器完成哪个平台账号登录/验证；
- `定位不唯一`：列出缺少的平台、账号、内容 ID/链接或项目映射；
- `文档创建失败/无权限`：说明已尝试在个人文档库创建的标题，并请求权限；
- `write_conflict`：给出现有与新快照 ID/关键差异，不覆盖。

不要声称“已写入”直到回读一致。
