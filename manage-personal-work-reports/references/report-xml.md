# 周报 XML 与最小化更新

## 目标结构

周报核心顺序为：

1. 标题 `个人工作周报（M.D-M.D）`
2. 上周遗留待办
3. 本周工作计划（保留图片与分栏结构；分栏文字可根据内容大表更新）
4. 三列表头：日期 / 逐日待办及完成情况 / 完成情况及未完成原因/复盘
5. 目标工作日行
6. 本周任务总结（周初保持空白或模板占位，周末再写）
7. 必要时的信息缺口

模板通常使用约 `106 / 322 / 500` 的列宽。以最新用户版本为准，不为追求固定列宽重建图片表格。

## 周初复制

- 用 Wiki 节点复制目标周紧邻的上一周有效周报到源周报所在的同一父节点；禁止新建空白文档或从零搭表。
- 复制后立刻验证新 node_token、obj_token、标题与父节点。
- 保留图片、表格、样式、OKR 结构和绿色“临时任务”。
- 保留“本周工作计划”区的图片、图片 token、grid/column 结构、列宽、链接顺序和样式；不得移动、删除图片或重建分栏。
- 允许根据内容大表当前值替换分栏内的文字 block。只写在制项目、本人负责稿件、明确节点和需要本人确认/审核/决策的动作；计划节点不得写成实际完成，冲突字段标记待确认。
- 清除旧日期的完成勾选、旧复盘和旧周总结。
- 更新标题、遗留待办、分栏文字、日期、逐日任务、右栏脚手架和空白总结；所有其他 block 保持原样。
- 写前保存“本周工作计划”区的逐块快照；写后对照图片与其他资源 token、grid/column 结构、列宽、链接顺序和样式。受保护内容出现差异即视为失败，停止后续写入并报告。

## 每日块级更新

- 先 fetch 当前 revision 和目标日期行。
- 生成仅针对目标行的变更：复选框状态、临时任务、右栏复盘。
- 写入前再次 fetch；revision 不一致就停止。
- 写入后回读目标行，并抽查前后日期未变化。
- 不因日报更新覆盖整篇文档。

## 周/月总结更新

- 只替换总结标题和正文块。
- 月末把“本周任务总结”改为月报总结时，先确认用户确实要求替换，而不是另建月报。
- 写明统计截止日、来源覆盖和信息缺口。

## 本地校验

将 Lark XML 片段写入临时文件后运行 `scripts/validate_report_xml.py`。片段可包含多个顶层元素；脚本会自动包装根节点。

周初排期示例：

```bash
python3 scripts/validate_report_xml.py report.xml \
  --mode plan \
  --expected-title '个人工作周报（8.3-8.7）' \
  --expected-date 8.3 --expected-date 8.4 --expected-date 8.5 \
  --expected-date 8.6 --expected-date 8.7
```

每日复盘示例：

```bash
python3 scripts/validate_report_xml.py report.xml \
  --mode recap --expected-title '个人工作周报（8.3-8.7）' \
  --expected-date 8.6
```

脚本只做结构性防错；最终仍必须通过飞书回读检查 revision、图片、样式和未修改区域。
