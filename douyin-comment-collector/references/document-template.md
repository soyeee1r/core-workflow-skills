# 固定文档模板：昨天表格版 v1

本模板来自用户明确指定的昨天案例。每篇扫楼报告必须使用同一章节顺序、同一字段名和同一表格表达；不得把正文自由改成引用块、卡片块或“评论观察”二级标题结构。

## 标题与总览

- 文档标题固定为：`<视频名称>｜评论与弹幕扫楼`。
- 首节固定为 `<h1>结论总览</h1>`。
- 依次写四段加粗标签行：`作品`、`采集时间`、`读取口径`、`展示口径`。
- 紧接一张单行汇总表，表头固定为：`评论实际读取`、`评论质量入选`、`弹幕实际读取`、`弹幕质量入选`、`视频时长`、`弹幕分段`。
- “展示口径”必须说明展示条数由质量决定，不固定为 10；不得为了凑数展示低价值内容。

## 评论四类

章节顺序和表头固定如下：

1. `<h1>高赞、高互动评论</h1>`：先写一段筛选口径，再用三列表格 `评论｜互动｜为什么值得看`。
2. `<h1>好评</h1>`：先写一段筛选口径，再用两列表格 `评论｜正向信号`。
3. `<h1>明确指出问题的评论</h1>`：先写一段筛选口径，再用两列表格 `原评论｜问题归纳`。
4. `<h1>重复率较高的话题</h1>`：先写一段统计口径，再用三列表格 `话题｜频次｜内容信号`。

每节展示多少行由质量决定，不设固定数量。没有达到门槛的内容时仍保留章节和表格，并用一行“本期未发现达到质量门槛的内容”如实说明。不得用 blockquote 逐条堆评论。

## 弹幕四类

弹幕沿用同一表格版式，不另起自由结构：

1. `<h1>弹幕概况</h1>`：先写全时长覆盖、分段成功和密度结论，再用三列表格 `时段｜弹幕数｜主要即时反应`；若不适合按时段拆分，仍保留表格，用一行总览表达。
2. `<h1>高赞、高互动弹幕</h1>`：先写筛选口径，再用三列表格 `时间点与弹幕｜互动｜为什么值得看`。
3. `<h1>弹幕好评</h1>`：先写筛选口径，再用两列表格 `时间点与弹幕｜正向信号`。
4. `<h1>弹幕明确指出的问题</h1>`：先写筛选口径，再用两列表格 `时间点与弹幕｜问题归纳`。
5. `<h1>弹幕重复率较高的话题</h1>`：先写统计口径，再用三列表格 `话题｜频次｜内容信号`。

## 建议与数据边界

- 最后一节固定为 `<h1>给内容团队的可执行建议</h1>`；每条建议使用“加粗引导句 + 连贯段落”，只出现一次。
- 文末用普通段落写 `数据边界：...`，不把“数据边界”升成标题。
- 不生成“给内容团队的补充建议”“质量入选明细”或任何附录式重复清单。

## 样式红线

- 只使用上述一级标题；不得使用 `<h2>` 自由拆分“评论观察”或“弹幕观察”。
- 评论与弹幕明细必须使用表格；不得使用 `<blockquote>` 逐条展示。
- 不使用 `<callout>`、分栏、装饰色或额外卡片块；表头统一 `light-gray`。
- 不展示评论人姓名、用户 ID、评论 ID、弹幕 ID、主页链接、去重键或隐藏账号标识。
- 同一文本只在最合适的一个表格中完整展示；其他分类只做归纳，避免重复铺陈。

## 发文档前硬检查

本地必须保存 `report.xml`，并逐项确认：

- 11 个固定一级标题顺序正确；
- 所有固定表头存在；
- 存在 `数据边界：` 普通段落；
- 不存在 `评论观察`、`弹幕观察`、`质量入选明细`、`给内容团队的补充建议`、`<h2>`、`<blockquote>` 或 `<callout>`；
- 回读飞书文档后结构和字段仍一致。

格式版本写为 `douyin-sweep-table-v1`。只有本地 `report.xml` 和飞书回读都通过检查，才能把 `document_verified_table_template` 标为 `true`。
