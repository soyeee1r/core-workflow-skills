# 抖音评论与弹幕扫楼

把每个抖音作品转换为一份可复核的评论 + 弹幕联合报告。用户未指定条数时，评论与回复从 100 条起步、每 50 条评估一次增量，连续两批没有新增价值时停止，硬上限 500 条；弹幕按作品全时长分段读取。文档和卡片只展示达到质量门槛的代表性内容，不按固定条数凑数。

## 0615 触发与默认动作

- 群聊同一条真人消息只要同时含 1–5 个抖音作品链接、真实 `@0615` 和“扫楼”，即创建任务；三者顺序不限。
- 有效任务创建后，0615 立即在原群回复“正在执行”，写明作品数、“评论按信息增量智能读取（100 条起步，最多 500 条）”和“同时抓取全时长弹幕”。不要再次确认是否开始。
- 每个作品独立采集、独立建或更新文档、独立发送一张卡片。最多并发 3 个，其余排队；一条失败不影响同批其他作品。
- 用户已授权的固定动作范围是：采集该批链接、在“查水表”创建或更新联合报告、用 0615 向触发群发送对应卡片和文档链接。
- 超过 5 个链接不静默截断，要求分批；混入其他平台链接时跳过并说明仅支持抖音。
- 私聊没有目标群时，不猜收件群；请用户在目标群发送“链接 + @0615 扫楼”。

## 不变口径

- 用户未指定条数时，评论与回复合计先读取至少 100 条，之后以 50 条为一批评估新增高互动观点、明确问题、正向信号和新话题；连续两批新增价值均低于门槛时停止，最多 500 条。公开可见范围不足 100 时如实记录。用户明确指定 100–500 条时按指定硬上限读取，不擅自改成自适应。
- 弹幕按视频完整时长以不超过 32 秒的区间逐段请求，覆盖到最后一段；合并后按弹幕 ID，或“时间点 + 正文”去重。弹幕为 0 只有在全时长请求成功且接口确实返回空列表时才记为 0。
- “读取量”和“展示量”分开：完整样本留在内部结构化文件，文档和卡片根据质量决定展示多少。不得每期固定 10 条，也不得为了凑数铺满全部样本。
- 评论和弹幕统一按以下优先级分析：高赞/高互动、好评、明确指出问题、重复率高的话题。同一内容可多标签；纯情绪吐槽不算明确问题，反讽不算好评。
- 文档和卡片禁止出现用户 ID、评论 ID、弹幕 ID、主页链接、去重键或隐藏账号标识。评论作者显示名仅在确有分析价值时使用；默认正文不依赖身份展示。
- 不下载头像、评论图片或视频媒体，不请求摄像头、麦克风、媒体、下载、远程调试、网站访问、钥匙串或浏览器权限。

## 采集后端

浏览器采集已被用户明确禁止。只能使用匿名公开接口和本技能的本地签名器：

1. 禁止 MediaCrawler 主程序、Playwright、Chrome 扩展、Chrome CDP、Codex Browser、独立浏览器、用户 Cookie 或任何浏览器回退。
2. 评论使用 `www.douyin.com/aweme/v1/web/comment/list/` 及回复分页；不得使用只返回十条热评的旧接口。
3. 弹幕使用 `www-hj.douyin.com/aweme/v1/web/danmaku/get_v2/`，单段不超过 32,000 毫秒。
4. 可为公开分享页和接口签名申请一次性匿名访客会话；只在当前采集进程内使用，不关联用户账号，不写入交付物。
5. 检测到验证码、访问限制或接口变化时停止，不绕过限制，也不切换浏览器。

## 执行

先完整读取 [references/collection-pipeline.md](references/collection-pipeline.md)，再运行联合入口。每个作品使用全新的输出目录：

```bash
node scripts/collect_sweep.mjs \
  --url '<douyin-video-url>' \
  --output-dir '<new-output-directory>'
```

默认不传 `--comment-limit`，由采集器执行 100 / +50 / 连续两批低增量停止 / 500 硬上限。只有用户明确指定 100–500 条时才追加 `--comment-limit <用户指定值>`。

联合入口会依次采集评论、全时长弹幕，执行去重和标准化，并生成 `sweep-summary.json`。回读摘要与首尾记录，确认评论、回复、弹幕、分段数、去重数、停止原因和视频标题一致。

## 价值筛选

完整读取 [references/prioritization.md](references/prioritization.md)，对评论和弹幕分别生成语义标注与质量视图。每类展示数量由质量决定；重复话题至少需要 3 条独立文本共同指向同一具体主题，近义表达合并。

## 飞书交付

采集、标准化和排序验证完成后，先完整读取 [references/document-template.md](references/document-template.md)，再完整读取 [references/feishu-delivery.md](references/feishu-delivery.md) 并执行：

- 每个作品只维护一篇评论 + 弹幕联合文档和一张 Card 2.0 卡片；卡片标题使用视频名称，包含文档链接。
- 文档归档到任小艺个人文档库“查水表”，评论和弹幕放在同一篇文档内；不得生成“质量入选明细”整节，内容团队建议只出现一次。
- 文档格式固定使用用户指定的“昨天表格版 v1”：分类标题、筛选口径、固定字段表格；不得自由改成“评论观察 / 弹幕观察 + 引用块”的结构。
- 文档用 `user` 身份，群卡片用 0615 的 `bot` 身份发送到触发消息的 `source_chat_id`。
- 同一 `video_id` 再次扫楼时更新已有文档，不新建重复文档。文档回读和卡片发送回执都成功后，任务才完成。
- 默认只发卡片。只有用户明确要求“卡片后再解释/技能展示”时，才在卡片发送成功后追加一条独立说明消息。

## 失败口径与边界

- 单个作品失败时，在原群写明 `第 i/n 条`、原链接、可用的视频标题或 ID、失败阶段和唯一下一步；不能只说“这条没完成”。
- 文档失败时不发送成功卡片；卡片失败时保留已创建文档，并按飞书交付参考中的降级规则提供链接。
- 仅收集当前公开可见的数据，控制频率并遵守适用的平台规则和个人信息保护要求。
- 不自动点赞、回复、关注、举报或发布内容；不做持续监控、代理池、跨账号批量或绕过限制。
